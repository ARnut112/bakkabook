# ดูแลโค้ด Bakkabook

เว็บใช้ HTML, CSS และ Vanilla JavaScript ตามเดิม การจัดโฟลเดอร์แยกหน้าที่ช่วยให้อ่านและแก้ไขได้ง่าย ส่วนเครื่องมือ build ทำงานก่อน deploy เท่านั้น

## ควรแก้ไฟล์ไหน

| งาน                                                          | ตำแหน่ง                                         |
| ------------------------------------------------------------ | ----------------------------------------------- |
| โครงหน้าและฟอร์ม                                             | HTML ทั้ง 6 หน้าในโฟลเดอร์หลัก                  |
| ตรวจค่าเชื่อมต่อบริการ                                       | `assets/js/core/configuration.js`               |
| Header, footer, icon, การ์ดหนังสือ และข้อความแจ้งเตือน       | `assets/js/core/common.js`                      |
| หนังสือและหมวดหมู่ตัวอย่าง                                   | `assets/js/data/books.js`                       |
| ข้อมูล, localStorage, Supabase, Auth, คำสั่งซื้อ และเรียก AI | `assets/js/services/store.js`                   |
| การทำงานของแต่ละหน้า                                         | `assets/js/pages/`                              |
| รูปแบบพื้นฐานและส่วนร่วม                                     | `assets/css/base/site.css`                      |
| ระยะห่างและการจัดวางหน้าร้าน/สินค้าแบบกระชับ                 | `assets/css/layout.css`                         |
| ตะกร้า ชำระเงิน และติดตามแบบกระชับ                           | `assets/css/pages/customer-compact.css`         |
| หลังร้านและออเดอร์แบบการ์ด                                   | `assets/css/pages/admin-compact.css`            |
| รูปแบบเฉพาะหน้า                                              | `assets/css/pages/`                             |
| การจัดวางมือถือและแท็บเล็ต                                   | `assets/css/responsive.css`                     |
| ลำดับรวม CSS สำหรับ source                                   | `assets/css/style.css`                          |
| รวมไฟล์และสร้างผลลัพธ์ deploy                                | `tools/build.mjs`                               |
| สิทธิ์ฐานข้อมูลและระบบสั่งซื้อ                               | `supabase/schema.sql` และ `supabase/orders.sql` |
| อ่านชื่อหนังสือและผู้เขียนจากปก                              | `supabase/functions/book-assistant/index.ts`    |

`order.html` ใช้ติดตามด้วยเบอร์โทร ส่วน `payment.html` ใช้ทำรายการออเดอร์เดียว คงการแยกสองหน้านี้ไว้เพื่อให้ลูกค้าเข้าใจขั้นตอนได้ง่าย

## ลำดับการโหลดที่ต้องรักษา

หน้า HTML โหลดสคริปต์แบบ `defer` ตามลำดับ: `config.js` → ข้อมูลตัวอย่าง → configuration → store → common → สคริปต์ของหน้า สคริปต์ยังแชร์ `BAKKA_CONFIG`, `BAKKA_SEED`, `BAKKA_CATEGORIES`, `BakkaStore` และ `BakkaUI` ตามเดิม หากเพิ่มไฟล์ที่พึ่งพาส่วนอื่น ให้ใส่หลังไฟล์นั้น

CSS source เริ่มจาก `style.css` แล้วนำเข้า `base/site.css` → `pages/product.css` → `pages/admin.css` → `responsive.css` → `pages/cart.css` → `pages/orders.css` ตามลำดับกฎเดิม จากนั้นใช้ `layout.css` → `pages/customer-compact.css` → `pages/admin-compact.css` สำหรับระยะและการจัดวางแบบกระชับ ลำดับมีผลต่อกฎที่เขียนทับกัน จึงไม่ควรเรียงใหม่เพียงเพื่อจัดชื่อให้เป็นหมวด

## ขั้นตอนก่อนส่งขึ้นเว็บ

```powershell
npm ci
npm run format
npm run format:check
npm test
npm run build
```

ใช้ `npm.cmd` แทน `npm` หาก PowerShell บล็อกสคริปต์ของ npm `npm ci` ต้องทำเมื่อตั้งเครื่องใหม่หรือ lockfile เปลี่ยน เครื่องมือพัฒนาอยู่ใน `devDependencies` จึงต้องติดตั้งส่วนนี้ก่อน build

หากมี Playwright และ Chromium/Edge ให้รัน `npm run test:browser` เพิ่มเติมเพื่อตรวจหน้าเว็บและขนาดหน้าจอ กำหนด `PLAYWRIGHT_PATH` และ `BROWSER_PATH` ได้ตามคำอธิบายใน README การทดสอบจำลองไม่ได้ยืนยันสิทธิ์ Supabase หรือโควตา Gemini จริง ต้องตรวจบริการจริงตาม SETUP หลังเชื่อมต่อ

`npm run test:layout` ตรวจคิวอาร์แบบพับ บันทึกสถานะ/ขนส่ง ยืนยันรับสินค้า และการจัดวางที่ 320/390/768/1280 พิกเซล ด้วยออเดอร์จำลองเท่านั้น ไม่เรียกบริการจริง การปรับเลย์เอาท์ชุดนี้ไม่ต้องรัน SQL เพิ่ม ให้อัปเดตไฟล์หน้าเว็บผ่านการ build/deploy ตามปกติ

## โค้ดอ่านง่ายกับไฟล์ที่ส่งจริง

แก้ source ใน HTML, `assets/`, `tools/` และ `supabase/` เท่านั้น ไม่แก้ไฟล์ใน `dist/` เพราะ build จะสร้างใหม่ทั้งหมด Prettier จัด source ให้ย่อหน้าและเว้นวรรคสม่ำเสมอ ส่วน esbuild ลดขนาดไฟล์ที่จะส่งจริง

Build รวม CSS เป็นไฟล์เดียวและลดขนาด JavaScript โดยยังรักษาลำดับสคริปต์ ชื่อ CSS/JS ในผลลัพธ์มี hash ตามเนื้อหา และ HTML อ้างอิงชื่อที่สร้างแล้ว Vercel จึงเก็บ cache ระยะยาวเฉพาะไฟล์เหล่านี้ได้ เมื่อเนื้อหาเปลี่ยนชื่อไฟล์จะเปลี่ยนด้วย

`config.js` สร้างจากค่าที่เปิดเผยได้และใช้ `no-cache` ผล build ไม่รวม SQL, ชุดทดสอบ หรือโค้ด Edge Function การแก้ Gemini ต้อง deploy Edge Function แยก ส่วนการเปลี่ยนฐานข้อมูลต้องรัน SQL ที่เกี่ยวข้อง ดูขั้นตอนใน SETUP

## บันทึกจุดผิดพลาดที่แก้ในการจัดระเบียบครั้งนี้

- เซิร์ฟเวอร์ในเครื่องลืมอนุญาต `payment.html` ทำให้หน้าทำรายการตอบ 404 เพิ่มหน้าไว้ในรายการที่อนุญาตและทดสอบการป้องกันไฟล์ภายในต่อ
- หน้าสินค้ารออ่านสถานะการจองก่อนผูกปุ่ม ทำให้การตอบกลับช้าจากบริการนั้นหน่วงการใช้ปุ่ม ผูกการทำงานหลักให้พร้อมก่อนอ่านข้อมูลเสริม
- เมื่อล้มเหลวในการส่งคำสั่งซื้อ ปุ่มกลับมาเป็นข้อความโดยเสียไอคอนลูกศร คืนเนื้อหาปุ่มให้ครบหลังจบคำขอ
- หน้า tracking อาจใช้เบอร์ที่แก้ในช่องค้นหาแล้วกับรายการเก่าที่ยังแสดงอยู่ เก็บเบอร์จากการค้นหาที่ให้ผลลัพธ์ชุดนั้นไว้ใช้เมื่อกลับไปทำรายการ
- Browser test อ้างตำแหน่งราคาจากโครง HTML เก่า ปรับ selector ให้ตรงกับ markup ปัจจุบัน

การปรับเหล่านี้แก้ข้อผิดพลาดและการรอที่ไม่จำเป็น โดยคงฟีเจอร์เดิม เช่น การค้นหา รายการโปรด ตะกร้า ติดต่อร้าน ชำระ QR แนบสลิป ติดตามออเดอร์ หลังร้าน และอ่านปก

## ผลตรวจหลังจัดระเบียบ

- ชุดทดสอบอัตโนมัติ 38 รายการผ่าน ครอบคลุมข้อมูล สิทธิ์จำลอง การจอง คำสั่งซื้อ เซิร์ฟเวอร์ และไฟล์ build
- ทดสอบเบราว์เซอร์ผ่านทั้ง source และ production build ที่ความกว้าง 390, 768 และ 1280 พิกเซล รวมขนาด desktop เริ่มต้น 1440 พิกเซล ไม่พบ JavaScript error ในสถานการณ์ที่ทดสอบ
- ตรวจว่าการแยก CSS และจัดรูปแบบยังคงลำดับกฎเดิม ส่วนสคริปต์ที่เปลี่ยนเฉพาะรูปแบบให้ผลหลัง compile เหมือนเดิม
- JavaScript และ CSS รวมสำหรับ production ลดจาก 145,704 เป็น 127,750 ไบต์ ประมาณ 12% ตัวเลขนี้เป็นขนาดไฟล์ก่อนบีบอัดเครือข่าย ไม่ใช่เปอร์เซ็นต์ความเร็วโหลดทั้งหน้า
- การทดสอบใช้ข้อมูลตัวอย่างและบริการจำลอง ไม่สร้างคำสั่งซื้อจริง ไม่เรียก Gemini จริง และไม่ได้ deploy ขึ้นบัญชีภายนอก

การจัดรูปแบบ SQL เปลี่ยนเพียงช่องว่างและ comment จึงไม่ต้องรัน SQL ใหม่เพราะการจัดรูปแบบครั้งนี้
