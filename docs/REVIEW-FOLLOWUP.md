# ผลแก้ไขจากรายงานทดลองใช้งาน 14 ตุลาคม 2026

## แก้แล้วในโค้ด (ยังไม่เผยแพร่)

- ปุ่มเพิ่มตะกร้าตรวจจำนวนรวมกับสต็อกที่แสดงก่อนบันทึก และแจ้งเมื่อเพิ่มไม่ได้ การตรวจจริงฝั่งฐานข้อมูลตอนสั่งซื้อยังทำงานเช่นเดิม สต็อกหน้าเว็บอาจเปลี่ยนได้ระหว่างเปิดหน้า
- คำค้น หมวด ลำดับเรียง และชั้นหนังสืออยู่ใน URL และอ่านกลับเมื่อเปิด/รีเฟรชหน้า พร้อมจำนวนหนังสือข้างหมวด
- ข้อความรองบนการ์ดเข้มขึ้นและใหญ่ขึ้น ปุ่มซื้อ/ดูรายละเอียดมีคำกำกับ พื้นที่กดอย่างน้อย 44px และลิงก์ปกมีชื่อสำหรับเครื่องมือช่วยอ่าน
- คำอธิบายการชำระเงินตรงกับตัวเลือก QR / ให้ร้านติดต่อ
- ย้ายทางเข้าหลังร้านไปส่วนท้าย
- เพิ่ม robots.txt, sitemap.xml สำหรับหน้าแรก, canonical และข้อความ Open Graph หน้าแรก พร้อม noindex สำหรับหน้าธุรกรรม/หลังร้าน ทั้งนี้ noindex ไม่ใช่ระบบควบคุมสิทธิ์

## ต้องยืนยันข้อมูลก่อนทำต่อ

- เจ้าของร้านยืนยันจัดส่งภายใน 2–3 วัน และติดต่อ LINE ID arnut369 เมื่อหนังสือมีปัญหา เพิ่มข้อความในหน้าสินค้า ตะกร้า และท้ายเว็บแล้ว โดยไม่ใส่ลิงก์ LINE/Facebook ยังไม่ได้กำหนดเงื่อนไขคืนเงินหรือระยะเวลาเก็บข้อมูลแทนร้าน
- สภาพหนังสือ มือหนึ่ง/มือสอง ปีพิมพ์ และภาพตำหนิต้องมาจากข้อมูลจริง รายงานนี้ไม่ได้ยืนยันข้อมูลเหล่านั้น
- เจ้าของร้านยืนยันใช้เลขคำสั่งซื้อคู่กับเบอร์โทร แก้หน้าเว็บและจัดทำ tracking-security.sql เพื่อปิดสิทธิ์ RPC ค้นด้วยเบอร์อย่างเดียวแล้ว ต้องรันไฟล์บนฐานข้อมูลจริงจึงมีผล
- ยังคงปิดการบันทึกสินค้าหมดตามคำสั่งเดิม รอการยืนยันหากต้องการเปลี่ยน

## งานที่ยังไม่ครอบคลุม

- ภาพแชร์/metadata รายสินค้าที่ส่งจากเซิร์ฟเวอร์, sitemap รายสินค้า และ Book/Product structured data ยังไม่ได้ทำ การเปลี่ยน document.title ฝั่งเบราว์เซอร์ไม่ทดแทนงานนี้
- ยังไม่ได้ทดสอบด้วยเครื่องมืออ่านหน้าจอจริงหรือ Safari/โทรศัพท์จริง

## เปิดใช้งานการติดตามแบบใหม่

1. สำรอง/ตรวจสอบว่าฐานข้อมูลเคยรัน orders.sql และ shipping.sql แล้ว
2. รัน supabase/tracking-security.sql ใน Supabase SQL Editor ได้ซ้ำ ไม่ลบรายการเดิม
3. Deploy หน้าเว็บชุดใหม่ทันทีหลังรัน SQL หน้าเว็บเวอร์ชันเก่าจะค้นด้วยเบอร์อย่างเดียวไม่ได้แล้ว
4. หากรัน orders.sql หรือ shipping.sql ซ้ำภายหลัง ให้รัน tracking-security.sql ตามอีกครั้งเพื่อคงข้อมูลพัสดุใน RPC แบบใหม่

ทดสอบด้วยเลขคำสั่งซื้อและเบอร์ที่ตรงกัน กรณีข้อมูลไม่ตรงต้องไม่แสดงรายการ และตรวจพัสดุ/ยืนยันรับสินค้าได้ตามเดิม ไม่ต้อง deploy Edge Functions ใหม่ ชุดนี้ยังไม่ได้ deploy หรือรัน SQL บนฐานข้อมูลจริง
